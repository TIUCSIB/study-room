## 排查 `Invalid declaration: PanelKey` 构建错(13:24)

用户报错:`[plugin:@tailwindcss/vite:generate:serve] app/app.vue?...&vue&type=style&index=0&lang.css:6:15: Invalid declaration: \`PanelKey\``。

**根因不是代码**,是**残留的旧 dev 服务器在服务旧代码**:
- `app.vue` 已无 `<style>` 块(121 行,`pnpm build` 通过两次),报错却指向 `?type=style&index=0` —— 那是删除前的旧 SFC 请求。
- 实测同时有 3 个 dev 服务器:3000(PID 25240,8:15:30 启动)、3001(PID 22452,8:33:02 启动)、3002(本次新起)。前两个是今早会话残留。
- 这些进程**只监听 IPv6 `[::1]`**,用 `127.0.0.1` 的 `connect_ex` 探测会误判为端口空闲 —— 这是我第一次判断失误的原因。Windows 上排查端口一律用 `netstat -ano | findstr :端口` 或 `Get-NetTCPConnection -LocalPort`,别用 loopback 探测。
- 新起的 dev 因 3000 被占,**静默退到 3002**,而用户看的是 3000 → 症状就是「改了文件还一直报旧错」。

**处置结果**:
- 清掉 3001 那个残留(PID 22452 及子进程 22464)→ 成功。
- 3000 那棵进程树(9424 → 25240/4508/21908/14492/24952,8:15 启动)**杀不掉**:`Stop-Process -Force` 和 `taskkill /F /T` 全部「拒绝访问」。原因是当前会话 `elevated: False`,那棵树属于**提权终端**。已确认用户身份 `DESKTOP-NTP8TMI\biscuit`、非管理员。→ 只能由用户关掉那个终端窗口,或管理员 PowerShell `taskkill /F /T /PID 9424`。
- 清 `.nuxt` + `node_modules/.cache/nuxt` 后重启,现干净运行在 3002;页面 200、日志无 Tailwind 报错、无 `Invalid declaration`。
- **教训**:清 `.nuxt` 前必须先停 dev 服务器,否则在跑的旧进程会立刻 500 `Cannot find module .nuxt/dev/index.mjs`(本次已复现)。

已把上述内容写入 `%TEMP%\lofi-study-room-handoff.md` 的 §4.2 与 §5.1。
