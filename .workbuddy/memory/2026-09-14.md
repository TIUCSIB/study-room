- `app.vue` 已无 `<style>` 块(121 行,`pnpm build` 通过两次),报错却指向 `?type=style&index=0` —— 那是删除前的旧 SFC 请求。

- 新起的 dev 因 3000 被占,**静默退到 3002**,而用户看的是 3000 → 症状就是「改了文件还一直报旧错」。

**处置结果**:

- 3000 那棵进程树(9424 → 25240/4508/21908/14492/24952,8:15 启动)**杀不掉**:`Stop-Process -Force` 和 `taskkill /F /T` 全部「拒绝访问」。原因是当前会话 `elevated: False`,那棵树属于**提权终端**。已确认用户身份 `DESKTOP-NTP8TMI\biscuit`、非管理员。→ 只能由用户关掉那个终端窗口,或管理员 PowerShell `taskkill /F /T /PID 9424`。

### 事故:`pnpm build` 与运行中的 `pnpm dev` 会互相锁死 `.nuxt`

在 dev 服务器(3001)运行期间执行 `pnpm build`,构建**卡死 9 分钟以上、零输出**(正常 29 秒)。停掉 dev 服务器后构建仍未恢复,最后 `taskkill /F /T` 掉构建进程(11144 → 22120 → 32156),清掉半写的 `.nuxt` 与 `node_modules/.cache/nuxt` 后重跑,29 秒通过。

**结论:本机不要在 `pnpm dev` 运行期间跑 `pnpm build`。** 先停 dev → 清 `.nuxt` → build → 再重启 dev。
(注意:此前有 3 次"dev 在跑同时 build"是成功的,所以这是**间歇性**的死锁,不能因为偶尔成功就当作安全。)

**另外**:清 `.nuxt` 前必须先停 dev 服务器,否则在跑的旧进程会立刻 500(此前已踩过一次)。
