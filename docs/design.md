# Lofi 自习室 · 设计文档

> 版本:v3.1 · 2026-09-14(Nuxt 重写版;v3.1 修正控件坞图标按钮、场景三级回退与 `.data` 路径描述)
> 状态:MVP 已实现。本文档是设计与令牌的唯一事实来源,`AGENTS.md` 引用此处。

## 1. 产品概念

**一句话(目标形态)**:整页就是一个 lofi 视频直播间——循环的氛围场景铺满屏幕,左下放歌,右边聊天,中间番茄钟,像和一群人一起熬夜学习。
其中「**右边聊天 / 中间番茄钟**」是方向、**尚未实现**:当前聊天与番茄钟都还是右下角可展开的面板(见 §2)。把它做成常驻的消息流与常驻倒计时,与 P0 登录是同一片区域的改造,建议并为一次做(§6)。

参考系:YouTube "lofi girl" 直播间、bilibili 学习直播区。
产品价值 = 陪伴感(有人在线)+ 氛围感(场景与音乐)。不做什么:排行榜、复杂社交。(登录原在「不做」清单里,2026-09-14 用户提出「聊天需登录后」已移出该清单,见 §4.1)

## 2. 页面布局

```
① 开机引导:全屏场景 + 左上打字机"listening now N ·"(闪烁小点)
   → 左下打字机"press any key to start ▮"(闪烁方块光标)
   → 任意键/点击 → CRT 通电动画进入主界面(每次进站都有,lofi.cafe 式仪式感)
② 主界面(全部裸文字铺在场景上,lofi.cafe 式):
┌────────────────────────────────────────────────┐
│ [N listening now ·]               [20:56 本地时间] │
│                                                │
│             （全屏循环 GIF/视频 / 降级动效场景）             │
│                                                │
│ [▶ ⏮ ⏭ ▮▮▮音量]     [番茄钟][Todo][聊天][我][全屏][设置] │
│ ...【Lofi 自习室】 当前曲名                ↑ 面板在控件坞上方展开 │
└────────────────────────────────────────────────┘
```

- 全屏背景按**三级回退**选源(见 §4.5):`scene.mp4` 循环视频 → `scene.gif` 循环 GIF → 代码渲染的"雨夜霓虹"场景(三团漂移光斑 + 雨丝 + 暗角)
- 右下角是控件坞(`ControlDock`,**像素图标按钮** + 悬停时在按钮上方弹出的自绘提示气泡):**番茄钟 / Todo / 聊天 / 我 / 全屏 / 设置**。前四者切换对应面板(同一时刻最多展开一个,再点一次收起);全屏走浏览器 Fullscreen API 并同步按钮态;设置打开 `SettingsModal`(§4.9)
- 聊天入口**有未读时显示方块提示点**(`animate-breathe` 的 6px 方块,用方块不用圆点是为了和 `▮` 的字符块语言一致),提示文案同时带上条数。理由:§1 说的陪伴感,前提是**看得见有人在说话**,不能只有点开才知道
- 「关于」不再是独立入口,已并入设置弹窗(§4.9)
  > **已知的取舍**:入口曾按「是否需要常驻可见」分层(右下放活动、右上放界面元信息),2026-09-14 用户决定**回退为全部集中在右下角一条** —— 单一落点更省心,分层后视线要在两角之间跳。**不要再重复提议分层**,除非同时给出「右侧常驻消息流」(§6 P0.5)那种能真正减少点击次数的方案。
- 所有浮层用 `.glass` 毛玻璃面板,保证在任意视频内容上可读
- **光标也是主题的一部分**:自绘 32×32 像素光标(`public/cursors/`,生成器 `tools/gen-cursors.py`)。当前为**样式 D「暖边」——奶白实心 + 1px 琥珀描边**,把主题暖色放在光标轮廓上。四个:`default` 奶白箭头 + 琥珀描边、`pointer` 反转(琥珀填充 + 奶白描边)、`text` 像素 I 型、`not-allowed` 灰色(禁用态,刻意与其余三个拉开,因为它是**语义信号**而非风格元素)。选型与硬约束见 AGENTS.md §5.7。**不用第三方光标素材**(许可不明)
- **四角 HUD 内边距必须一致(统一 20px)**:左上在线数(`ListeningNow`)、右上时钟、左下播放器、右下控件坞。它们由**四个互不相关的 padding 各自决定**,改一处很容易忘掉另一处 —— 曾出现左上 `pt-4`(16px)、右上 `pt-6`(24px) 相差 8px,以及下沿 `bottom-4`(16px) 与上沿 20px 不一致。现已统一为 **上 20 / 下 20 / 左 20 / 右 20**。
  唯一例外:引导页左下「按任意键开始」(`BootGate`)仍是 `bottom-3`(12px),属引导页的独立构图,不在主界面 HUD 之内。
  另注:左上文字(24px)与右上时钟(30px)字号不同且各自独立定位,**没有共用基线**;上沿对齐后视觉上已齐。若要求基线严格对齐需再给左上补约 4px 顶部偏移 —— 但 `ListeningNow` 是常驻组件(引导页与主界面共用同一实例、要求两阶段逐像素同位),**不要改用 flex `items-baseline` 让兄弟元素决定它的位置**,否则时钟一出现左侧文字就会下移,破坏该不变量。

## 3. 风格:像素电台 CRT 终端(参考 lofi.cafe)

风格手法(五件套,均已实现):
1. **字体**:全站像素字栈 `VT323`(数字/拉丁,Google Fonts)+ `Fusion Pixel 12px`(中文,jsDelivr webfont)。基准字号 19px,计时器 64px
2. **荧光字**:`glow` / `glow-info` 工具类 —— 多层 text-shadow 模拟 CRT 荧光粉(琥珀主色/雾蓝信息色)
3. **扫描线**:`crt-lines` 工具类 —— 3px 周期横纹,`mix-blend-mode: overlay`,9s 缓慢下移
4. **开机动画**:`crt-boot` —— 进站画面从一条横线展开并闪亮(scaleY 0→1 + brightness 14→1)
5. **无卡片化**:文字直接铺在场景上(顶栏);必须的面板用 `glass`(近黑底 + 1px 暖描边 + 直角);进度条是 `▮▮▮▯▯` 字符块;按钮用**像素图标**(`pixelarticons` 图标集,经 `@nuxt/icon` 本地渲染)。图标渲染统一走 `icon-pixel` 工具类 —— **24px 即原生网格 1:1,并 `shape-rendering: crispEdges` 关掉抗锯齿**,否则像素图被插值、与硬边像素字违和;要辉光用 `glow-icon`(`filter: drop-shadow`),因为 `glow` 的 `text-shadow` 对 SVG 图形无效。图标集选型与许可说明见 AGENTS.md §5.5。**悬停提示用自绘气泡 `tip`**(`components/PixelTip.vue`,显示在元素上方),**禁用原生 `title`** —— 详见 AGENTS.md §5.8。键盘操作:空格播放/暂停、←→ 切歌

### 色彩令牌(唯一来源)

定义在 `app/assets/css/main.css` 的 `@theme`,**组件内禁止硬编码颜色**:

| 令牌 | 色值 | 用途 |
|---|---|---|
| `void` | #0D0A12 | 页面底色(近黑,衬托荧光) |
| `panel` | rgb(10 8 14 / .62) | 终端面板底 |
| `line` | rgb(246 193 119 / .22) | 面板描边(暖) |
| `accent` | #F6C177 | 暖琥珀:主行动色(计时/按钮辉光) |
| `info` | #A8C4E8 | 冷雾蓝:信息与他人昵称 |
| `cream` | #EBEBEB | 主文字(荧光白) |
| `dim` | #9B93A8 | 弱文字 |
| `danger` | #E88A8A | 结束/危险动作 |
| `ink` | #17121F | 实色按钮上的深字 |

原则:近黑底 + 单一暖琥珀荧光 + 冷蓝信息色;暖色永远留给"行动与成就",冷色留给"信息与他人"。
文案语气:轻、暖、不训话。("灯还亮着,休息一下也没关系" 而非 "坚持就是胜利!")

## 4. 功能规格

### 4.1 身份

**当前(已实现)**:昵称即身份(localStorage,首次进页弹窗)。无登录,长度 ≤12,过 `sanitizeText`。

**已定变更(用户 2026-09-14 决策,尚未实现)**:聊天需**登录后**才可用;认证方式为**第三方 OAuth(GitHub)**;场景/音乐/番茄钟保持免登录。**本轮只记录不动手。**

落地要点(不要只加一个登录弹窗,以下都是连带必改项):

1. **服务端信任模型要翻转**。现在 `GET /api/chat?nick=` 与 `POST /api/chat { nick, text }` 的身份完全由请求方自称,服务端只过 `sanitizeText` 就采信 —— 任何人都能用任意昵称发言。登录后 `nick` 不再从查询串/请求体读取,一律由**服务端会话**判定。`POST /api/pomodoros` 同样只靠自称 `nick`,要一起收口。
2. **先定一个前置问题:未登录能否「只看不发」?**
   - 若能只读(推荐):只有 `POST /api/chat` 需鉴权,`EventSource` 保持免鉴权 —— 这样正好绕开「EventSource 不支持自定义请求头」的限制,实现大幅简化,在线人数也不失真。
   - 若完全不可见:SSE 也必须鉴权,令牌只能走 Cookie(同源 `SameSite=Lax` 可行)或查询串(会进访问日志,不推荐)。
3. **GitHub OAuth 流程(三步,不需要新增依赖)**:`/api/auth/github` → 302 到 GitHub authorize(带 `state`) → 回调 `/api/auth/github/callback?code=` → 服务端用 code 换 token → `GET api.github.com/user` 取身份 → 建本地会话。全部可用 `$fetch` 手写;若确实想引 OAuth 库,按 AGENTS.md §5.6 先说明不可替代理由。
4. **身份主键用 GitHub 数字 `id`,不要用 `login`**(login 可改名)。显示名默认取 `login`,允许站内改成 ≤12 字,但要处理重名。
5. **密钥与安全**:`client_secret` 必须走环境变量(`.gitignore` 已含 `.env`);**本仓库是公开仓库,绝不能提交 secret**。必须实现 OAuth `state` 防 CSRF。会话建议用 HMAC 自签 Cookie(无需服务端存储,契合当前无状态架构)。
6. **存储扩一张表**:`.data/users.json`(github id → 显示名、首次登录时间),读写仍集中在 `server/utils/store.ts`。
7. **顺带重新评估 §4.2「历史不做持久化」**:有账号之后用户通常期望看到自己的历史消息,该前提可能推翻。

### 4.2 实时聊天(SSE + POST)
- 下行:`GET /api/chat?nick=` SSE 流,事件 `chat` / `system` / `presence`
- 上行:`POST /api/chat { nick, text }`
- 在线名单广播、进出系统消息、断线浏览器自动重连(EventSource 原生)
- 客户端仅保留最近 200 条
- 历史:不做持久化(直播间语义,进房只看当下)

### 4.3 番茄钟(lofi.cafe 式,控件坞面板)
- 由右下角控件坞「番茄钟」按钮开关;显示:大号像素数字倒计时,下方 `Start` / `+5:00`
- **默认时长来自设置页**(`lofi-room:pomodoro-minutes`,当前默认 5 分钟);空闲时点时间数字在 5/25/50 预设间轮换,运行中 `+5:00` 随时加 5 分钟。面板内切换只是**临时**改动,不写回设置
- 运行中:`Pause` / `Resume` / `End`(结束并记录,满 1 分钟才上报);到点自动完成
- 完成或结束 → `POST /api/pomodoros { nick, minutes }` 服务端入账(页面不展示统计,纯记录;后续做专注报告时再消费)
- 关页面时未结束的会话自动入账

### 4.4 音乐播放器(壳,左下角传输条)
- `GET /api/tracks` 扫描 `public/music/`(mp3/flac/ogg/wav/m4a)
- 传输条:`▶/⏸`(play/pause)、`shuffle`、`prev`、`next` + 10 格 ▮ 块状音量(点击设音量);图标全部来自 `pixelarticons`
- 下方 `... 【Lofi 自习室】 当前曲名`,点歌名切歌;播完自动下一首
- 键盘:空格播放/暂停,←→ 切歌(输入框聚焦时不劫持)
- 空歌单显示引导文案;音源接入(在线电台/上传)是后续独立任务,接口已隔离在该组件内

### 4.5 场景背景(三级回退)
`VideoBackdrop` 挂载时用 `fetch(HEAD)` 按 content-type 探测(缺失文件会被 SPA 回退成 200 的 HTML,不能只看状态码):
1. `public/videos/scene.mp4` 循环视频
2. `public/videos/scene.gif` 循环 GIF(当前使用 lofi.cafe 的像素云海,自用;公开部署前需换授权素材)
3. 代码渲染的"雨夜霓虹"降级场景

之上叠加 `crt-lines` 扫描线与暗角;视频/GIF 静音自动循环。
视频是用户自备资产(版权自行把关);README 已说明

### 4.6 开机引导(BootGate)

由 `BootGate.vue` 实现:全屏场景之上先只显示打字机引导,任意键/任意点击(含打字中途)即跳过并进入主界面。

- 进站先只显示场景:左上打字机逐字打出 `listening now N` + 闪烁小点;完成后左下打出 `press any key to start` + 闪烁方块光标 ▮
- 任意键/任意点击立即进入主界面(打字中途按也会跳过),主界面播放 `crt-boot` 通电动画
- 引导页的在线数走 `GET /api/presence`(此时尚未建立 SSE 连接),进入主界面后由 SSE 的 `presence` 事件接管
- 「正在自习 N 人」是常驻组件 `ListeningNow.vue`,**引导页与主界面共用同一个实例、不重建**,打字机只跑一次

### 4.7 Todo 面板(本地)
- 由控件坞「Todo」按钮开关;纯本地 localStorage(`lofi-room:todos`,键名统一登记在 `app/composables/useSettings.ts`),不做服务端同步
- 添加(≤60 字)、勾选完成(▣/▢ 字符块)、悬浮删除;头部显示剩余件数,文案轻暖

### 4.8 控件坞(ControlDock)

**入口集中在右下角一条**(2026-09-14 定稿;2026-09-14 增补「我」后为六个):

- 一排**像素图标按钮**(`pixelarticons:clock` / `checklist` / `comment` / `user` / `expand` ↔ `close` / `settings-2-sharp`):番茄钟 / Todo / 聊天 / 我 / 全屏 / 设置
- 前四者切换对应面板(面板堆叠在控件坞上方,同一时刻最多展开一个,再点一次收起);全屏走浏览器 Fullscreen API 并同步按钮态;设置打开 `SettingsModal`(§4.9)
- 聊天入口**有未读时显示方块提示点**(6px `bg-accent` + `animate-breathe`;用方块不用圆点是刻意对齐 `▮` 的字符块语言),提示文案同时带条数。依据:§1 的陪伴感,前提是**看得见有人在说话**,不该只有点开才知道
- 「关于」不再单列,已并入设置弹窗(§4.9)
- **曾经试过按「是否需要常驻可见」分层**(右下放活动、右上放界面元信息),2026-09-14 用户决定回退为单一落点:分层后视线要在两个角之间跳,反而更麻烦。**不要再重复提议分层**,除非同时给出能真正减少点击次数的方案(如 §6 P0.5 的常驻消息流)

### 4.9 设置弹窗(SettingsModal)

- **形态:居中玻璃模态**(`ModalShell` 统一遮罩 + `.glass` 卡片;点遮罩 / Esc / 「关闭」都能退出)
- **不做成独立路由**,理由是硬的:整站是单页沉浸架构(`h-screen`,body 锁 `overflow:hidden`),切路由会卸载并重建 `MusicPlayer` —— `<audio>` 元素被销毁,**正在放的音乐直接断**;同时 SSE 断连重连(`listening now` 掉一下,还可能刷出一条「有人离开/加入」的系统消息),`VideoBackdrop` 的 GIF 也要重新加载。设置是低频、成组的内容,模态更合适。
- `ModalShell` 的 `closable={false}` 专供首次昵称弹窗 —— 那个不能关,否则用户会把自己关进一个没有身份的房间里。

四组内容:

| 分组 | 项 | 说明 |
|---|---|---|
| 身份 | 改昵称(≤12 字) | **此前完全没有入口**(昵称只在首次弹窗写过一次)。改名后 `useChat` 会以新身份重连 SSE |
| 专注 | 番茄钟默认时长 5 / 25 / 50 | 写 `lofi-room:pomodoro-minutes`,作用于**下次**打开番茄钟;运行中的那一轮不受影响 |
| 信息 | 关于 + 快捷键 | 原独立「关于」面板的内容并入此处 |
| 数据 | 清空本地数据 | 只清 `lofi-room:*` 前缀的键,不动同域下其他应用;不可逆,所以**两步确认**(4 秒内没跟进自动放弃) |

**一并修掉的隐患**:`useChat.connect()` 原来第一行是 `if (!nick.value || !import.meta.client || source) return`,而监听是 `watch(nick, v => { if (v) connect() })` —— **昵称从 A 改成 B 时不会重连**。`EventSource` 的身份(`nick`)是建立时写死在查询串里的,于是服务端在线名单会一直挂着**旧名字**,新名字永远不出现。此前因为没有改昵称的入口,这个 bug 是**休眠**的;设置页一做它立刻变成线上问题,故一并改为「先 close 再新建」。**将来做 P0 登录时同理**:身份切换必须重建连接。


### 4.10 用户面板(UserPanel)

- 由控件坞「我」按钮开关,宽 320px(与聊天 / Todo 面板同宽),三块内容:
  | 块 | 内容 | 数据来源 |
  |---|---|---|
  | 身份 | 昵称 + 内联改名(≤12 字) | `localStorage`(经 `app.vue` 的 `confirmNick`) |
  | 专注记录 | 今日分钟 / 今日番茄数 / 连续天数 / 累计分钟,附「全房今天已记 N 个」 | `GET /api/pomodoros?nick=` |
  | 房间里的人 | 在线人数 + 昵称列表,**自己排最前并用暖色高亮** | SSE `presence` 事件 |
- **为什么要有这一格**:昵称此前只在首次弹窗写一次,之后用户既看不见「我是谁」,也看不见自己的积累。§1 的陪伴感前提是**看得见自己也在房间里**,不只是看得见别人
- 改名入口与设置页(§4.9)**重复是故意的**:设置页是成组的低频配置,这里是「点我即改」。改名后走同一个 `confirmNick`,`useChat` 以新身份重连 SSE,记录按昵称重新拉取
- 记录接口按昵称聚合,所以**改名即换一份统计** —— 这是当前无账号模型的固有行为(§6 P0 登录才解决)

## 5. 技术架构

- **Nuxt 4 全栈**:前端 `app/`,服务端 `server/`(Nitro)
- **样式**:Tailwind CSS v4(`@tailwindcss/vite`),令牌在 `@theme`;硬性规范见 AGENTS.md §5(≤300 行/文件、组件复用优先、`@` alias、禁止 scoped 样式)
- **聊天为什么不走 WebSocket**:Nuxt 4.5 新服务端引擎(`@nuxt/nitro-server`)对 h3 v1 的 `defineWebSocketHandler` 返回 426;SSE + POST 是纯 HTTP,行为稳定且满足聊天语义。若将来要双向高频同步(如协作白板)再评估
- **持久化**:`server/utils/store.ts` 读写**项目根** `.data/pomodoros.json`(路径来自 `join(process.cwd(), '.data')`,不是 `server/.data/`);换 SQLite 只动这一个文件。`statsFor()` 已实现 today/streak/total/roomTodayCount 五个指标,供后续专注报告消费
- **客户端设置(纯本机)**:`app/composables/useSettings.ts` 是 **localStorage 键名的唯一登记处**(`lofi-room:nick` / `:todos` / `:pomodoro-minutes`)。键名此前散落在各组件里,多一处就多一次拼错的机会;**新增设置项先在这里登记键名**,不要在组件里写字面量。设置不上服务端 —— 与「数据只存在这台机器上」一致
